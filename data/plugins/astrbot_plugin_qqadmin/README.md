## 🤝 介绍

- 本插件利用Onebot协议接口，实现了QQ群的各种管理功能，旨在帮助用户更方便地管理群聊。  
- 功能包括：禁言、全体禁言、踢人、拉黑、改群昵称、改头衔、设管理员、设精华、撤回消息、改群头像、改群名、发群公告等等。
- 插件现已提供前端配置面板，支持默认群模板、按群独立配置、群头像与群名展示、权限配置折叠管理等能力。
- 同时本插件实现了权限控制：超级管理员 > 群主 > 管理员 > 成员。
- 除 aiocqhttp 外，插件也适配了 QQ 官方机器人（qq_official / qq_official_webhook），群管接口按官方 API 调用。

## 📦 安装

在astrbot的插件市场搜索astrbot_plugin_qqadmin，点击安装即可  

## 🤖 QQ 官方机器人适配

官方群聊的群号与成员号都是 openid 字符串，插件会自动把群管操作切换到官方接口：

| 功能 | 官方接口 |
| --- | --- |
| 禁言 / 解禁 | `POST /v2/groups/{group_openid}/restrict_chat_setting` |
| 踢人 / 拉黑 | `POST /v2/groups/{group_openid}/batch_remove_members` |
| 撤回引用消息 | `DELETE /v2/groups/{group_openid}/messages/{message_id}` |
| 机器人自身角色 | `GET /v2/groups/{group_openid}/bot_state` |
| 其他成员角色 | 优先取事件里的 `author` / `mentions`，兜底 `GET /v2/groups/{group_openid}/members/{member_openid}` |
| 进群审核 | 轮询 `GET /v2/groups/{group_openid}/join_request_list`，审批用 `POST /v2/groups/{group_openid}/approval_join_request/{member_openid}` |

群成员角色（群主/管理员/成员）直接来自官方群消息事件里的 `member_role`，因此权限判断与「我动不了群主」这类检查不需要额外接口；群消息里的 @ 目标也会从 `mentions` 与文本中解析出来。
官方禁言接口按“绝对到期时间”计时（OneBot 是相对秒数），本地只精确到秒且请求还有往返耗时，插件会向上取整并多补 1 秒，保证实际禁言不短于设置值（官方上限 30 天）。
官方未开放的接口会直接回复“官方机器人暂不支持xxx”，该提示不影响 aiocqhttp 适配器。
这些功能包括：全体禁言、群昵称、头衔、管理员、群精华、群头像、群名、群公告、群成员列表、群文件、批量撤回。
另外官方要求机器人自身是群管理员才能禁言；踢人/拉黑与群成员信息接口属于内邀能力，未开通时调用会回复接口报错（如“应用无接口访问权限”）。

### openid 显示成「昵称(openid)」

官方平台的 openid 对人不可读，插件维护了一个**按群独立的 openid → 昵称池**（落在插件数据库的 `nicknames` 表，重启后自动从库里预热回内存）：
群消息里的 `author` / `mentions` 昵称、入群申请带的昵称都会顺手记录，展示时优先取用。例如：

```
禁言【lumio(EB4E842FE856B5073A152CC9277FD1B6)】：
赞同(1/3)
反对(0/3)

用户[lumio(EB4E842FE856B5073A152CC9277FD1B6)]已被禁言60秒
```

池里没有的成员仍只显示 openid；OneBot 侧展示保持原样（群名片/号码），名额取不到时也不会额外查接口。

### 进群审核与群成员变动在官方平台怎么走

官方把 `GROUP_JOIN_REQUEST`（入群申请）、`GROUP_MEMBER_ADD/REMOVE`（群成员进退）、`GROUP_ADD_ROBOT/DEL_ROBOT`（机器人进退群）都放在 intent `GROUP_MEMBER_EVENT (1<<24)` 里，botpy 没有这个开关，AstrBot 上游也没有订阅这些事件。本插件在加载时把支持注入进 botpy（见 `core/official_group_events.py`），因此 **AstrBot 核心源码保持原样，升级不用重新打补丁**：

- 注入内容：`ConnectionState` 的事件解析器、`botpy.Client` 的 `1<<24` intent 位、客户端的 `on_group_*` 回调。
- 生效范围：Websocket 与 Webhook 两种接入方式都覆盖。
- 唯一前提：先在 QQ 开放平台申请到「群成员事件」权限。**权限没开通时带上该 intent 位会被网关拒绝，导致 websocket 鉴权失败、连不上**，官方文档对此有明确说明。
- 启动日志若出现「群成员事件注入未生效」，说明注入没装上（例如缺少 qq-botpy），此时入群申请退回轮询处理，退群通知/进群欢迎/进群禁言不会生效。

事件到达后：入群申请会立即按规则自动批准/驳回（与下面的轮询共用去重，不会重复处理），群成员进退群会走进群欢迎、进群禁言、退群通知、退群拉黑。

每条入群申请都会打印判定日志，便于排查为什么被批准/驳回，例如：

```
[进群审核]群30584554AA2BF4E72BD3B8F27A70339D 收到入群申请：小明(FE003FAF76C4817251FDC128A16753BB) 验证信息=暗号
[进群审核]群30584554AA2BF4E72BD3B8F27A70339D 用户FE003FAF76C4817251FDC128A16753BB 黑名单=未命中、黑词=未命中、白词=命中(暗号) → 批准（命中进群白词）
```

为避免事件订阅缺失（未开通权限、webhook 未勾选）导致功能失效，插件同时保留**每 10 秒轮询** `join_request_list` 兜底（覆盖保存过 `/进群审核 开` 的群）：命中白词/黑词、黑名单、次数上限等原有规则时自动批准/驳回（拉黑用户会同时带上官方黑名单），其余按人工审核把申请通知到群里，管理员引用该通知回复「批准 理由」/「驳回 理由」即可；开启 `admin_audit` 时官方平台没有管理员私聊映射，会静默处理不再通知。

> 收不到入群申请通知时，先看启动日志里的两条 `[进群审核]` 记录：一条会列出**已开启进群审核的群**（为空说明还没在群里发过 `/进群审核 开`，官方平台没有群列表接口，插件只能轮询它记录过的群），另一条会提示**群成员事件是否开启**。
轮询频率为每群每分钟 6 次（`join_request_list` 限 30 QPM），开启进群审核的官方群建议不超过 5 个。
`进群等级` 门槛已移除：官方接口不提供申请人 QQ 等级（见 [用户申请加群事件](https://bot.q.qq.com/wiki/develop/api-v2/autogen/event/group_join_request.html) 的事件体），OneBot 侧依赖的 `qqLevel` 只是协议端扩展字段。
白词/黑词匹配的是**申请人的验证信息**（`verify_info.verify_message` 或管理员问答的答案），所以申请人没填验证消息时（日志里显示 `验证信息=无`）无从匹配，只会走「未命中」分支；匹配不区分大小写。
`退群通知`、`进群欢迎`、`进群禁言` 只能由 `GROUP_MEMBER_ADD/REMOVE` 事件驱动，官方没有可轮询的成员列表接口，因此**必须开通群成员事件**才会生效（启动日志里会明确提示）。

## 🤝 配置

进入 AstrBot 插件设置页后，可直接使用本插件自带的前端配置面板进行管理。

### 前端面板说明

在Astrbot插件页面，点击插件logo图进入详情页面，在插件行为下点击页面1中的“打开”，即可进入群管插件的前端配置面板。

- 左侧为群列表，支持按群名或群号搜索，也可以手动同步最新群列表。
- 右侧为当前选中群的配置表单，顶部显示当前群名称，下方直接展示可编辑配置项。
- “默认群”就是全局默认模板。新群或未单独配置的群，会优先继承默认群配置。
- 每个具体群的第一项配置为“跟随默认配置”。
  开启时，该群会直接继承默认群，其他配置项会自动置灰不可编辑。
  关闭时，该群就会保存自己的独立配置。
- 切换群时，当前页面的修改会自动触发保存，不需要先手动点击保存按钮。
- 指令权限管理已做成可折叠区域，默认收起，需要时再展开编辑。
- 面板会显示群头像、群名称和群号；群名称会优先通过 QQ 接口获取，并在插件内做缓存。
- 如果某个群在实时列表中显示为 0 人，插件会视为该群已失效，并自动清理对应的缓存与配置数据。
- 目前面板右上角提供独立的浅色 / 深色 / 自动主题切换按钮，后续可在框架支持后再进一步与 AstrBot 主题联动。

### 配置思路

- 先把通用规则配置在“默认群”中，作为全局模板。
- 仅对少数特殊群关闭“跟随默认配置”，再按需覆盖个别设置。
- 大多数群如果保持跟随默认配置，后期维护会轻松很多。
